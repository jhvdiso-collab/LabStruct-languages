# Отчёт по лабораторной работе №1

**Тема:** абстрактные структуры данных. **Вариант:** 2, АВЛ-дерево.

Перед сдачей заполнить ФИО, группу и сведения о преподавателе по шаблону кафедры.

## Цель и реализация

Изучить представление данных, алгоритмы добавления, поиска, удаления и чтения,
сравнить трудоёмкость операций. Реализованы массив, односвязный и двусвязный
списки, стек и очередь на C++ и Go; АВЛ — на C++.

Массив хранит буфер, длину и вместимость; при заполнении вместимость удваивается.
При вставке/удалении по индексу сдвигается хвост массива. Односвязный список
содержит указатель на следующий узел. Двусвязный дополнительно хранит предыдущий
узел и указатель на хвост. Стек добавляет и удаляет голову цепочки (LIFO),
очередь добавляет хвост и удаляет голову (FIFO).

В АВЛ каждый узел хранит ключ, высоту и двух потомков. После вставки/удаления
пересчитываются высоты на пути к корню. При разнице высот поддеревьев ±2
выполняется одинарный или двойной поворот. При удалении узла с двумя потомками
его ключ заменяется минимальным ключом правого поддерева; затем этот ключ
удаляется из правого поддерева. Поиск сравнивает ключ и выбирает одно поддерево.
Дубликаты ключей не добавляются. Инварианты: строгий порядок BST, корректная
сохранённая высота, разница высот поддеревьев не более 1.

Интерфейс: `--file путь --query 'команда имя аргументы'`. Команды и граничные
условия перечислены в README. Все операции проверяют допустимость входа.

## Сложность операций

В таблицах `n` — число элементов выбранного контейнера. Это стоимость операции
**в памяти**, без разбора всего файла и вывода результата. Для массива указан
худший случай, кроме отдельно отмеченного амортизированного.

| Структура | Операция | Время |
|---|---|---|
| Массив | Создать пустой, длина, получить/заменить по индексу | O(1) |
| Массив | Добавить в конец | O(1) амортизированно, O(n) при расширении |
| Массив | Вставить/удалить по индексу | O(n); удаление последнего O(1) |
| Массив | Чтение всех элементов, освобождение буфера int | O(n), O(1) соответственно |
| Односвязный список | Создать, вставить/удалить голову | O(1) |
| Односвязный список | Вставить/удалить хвост | O(n) |
| Односвязный список | Вставить/удалить до/после элемента, указанного индексом | O(n) |
| Односвязный список | Поиск/удаление первого значения, доступ по индексу, длина | O(n) |
| Односвязный список | Прямое/обратное чтение, освобождение | O(n) |
| Двусвязный список | Создать, вставить/удалить голову или хвост | O(1) |
| Двусвязный список | Вставить/удалить до/после элемента, указанного индексом | O(n) |
| Двусвязный список | Поиск/удаление значения, доступ по индексу, длина | O(n) |
| Двусвязный список | Прямое/обратное чтение, освобождение | O(n) |
| Стек | Создать, push, pop, чтение вершины | O(1) |
| Стек | Чтение всех элементов, освобождение | O(n) |
| Очередь | Создать, push, pop, чтение головы | O(1) |
| Очередь | Чтение всех элементов, освобождение | O(n) |
| АВЛ | Создать пустое дерево | O(1) |
| АВЛ | Вставка, поиск, удаление | O(log n) |
| АВЛ | Симметричный обход, освобождение | O(n) |

Поиск узла по индексу требует обхода даже в двусвязном списке; сами перестановки
известных связей — O(1). Поэтому нельзя объявлять всю индексную команду O(1).
Длина списков в этой реализации вычисляется обходом, а не хранится отдельно.
В Go память освобождает сборщик мусора; таблица освобождения относится к C++.

Обоснование: индекс массива вычисляет адрес непосредственно, поэтому доступ
O(1); сдвиг до n элементов даёт O(n). При удвоении массива суммарное число
копирований за n добавлений ограничено геометрической суммой O(n), отсюда
амортизированное O(1). Поиск в списке посещает до n узлов. Операции стека и
очереди меняют постоянное число указателей. Минимальное число узлов АВЛ высоты h
удовлетворяет N(h) = 1 + N(h−1) + N(h−2), поэтому высота O(log n);
вставка и удаление проходят путь этой длины, каждый поворот занимает O(1).
Полный обход посещает каждый элемент один раз, то есть O(n).

Каждая структура занимает O(n) памяти. У массива возможен резерв вместимости,
у связных структур добавляются указатели. Высота и рекурсивный стек АВЛ — O(log n).
Сериализация/PRINT создают буфер O(n). Обратное чтение односвязного списка также
требует O(n) дополнительной памяти; у двусвязного обратный проход использует `prev`,
но форматирование результата всё равно создаёт буфер.

**Стоимость файлового интерфейса:** при каждом запуске загружается вся база.
Пусть `N` — общее число элементов, `k` — количество контейнеров, `t` — количество
ключей дерева. Загрузка линейных структур O(N); восстановление дерева вставками
O(t log t). C++ использует реестр `std::map`, что добавляет O(k log k) на загрузку
и O(log k) на поиск имени. Go использует map (ожидаемо O(1) на обращение), при
сохранении сортирует имена за O(k log k). Запись значений O(N + k).
Одна команда не является O(1) целиком только потому, что её операция в памяти O(1).

## Достоинства, недостатки и применение

| Структура | Достоинства | Недостатки | Пример применения |
|---|---|---|---|
| Массив | Быстрый индексный доступ, локальность памяти | Сдвиги при вставках, перераспределение буфера | Таблицы чисел, последовательная обработка |
| Односвязный список | Простая вставка в голову, стабильные адреса узлов | Нет прямого обратного обхода, поиск O(n) | Цепочки элементов, свободные блоки |
| Двусвязный список | Обход в обе стороны, быстрые операции с известным узлом | Два указателя, сложнее поддерживать связи | История переходов, LRU со вспомогательным индексом |
| Стек | Простые операции O(1), порядок LIFO | Доступ преимущественно к вершине | Отмена действий, разбор выражений, DFS |
| Очередь | Простые операции O(1), порядок FIFO | Нет быстрого произвольного доступа | Задания обработчика, BFS |
| АВЛ | Гарантированные O(log n), отсортированный обход | Высоты и повороты усложняют изменения | Упорядоченное множество, поиск ключей |

## Контрольные примеры и визуальные формы

Запускать команды последовательно, каждый пример — в новом файле. Полные
автоматизированные сценарии находятся в `tests/cli.py`.

### Массив

```text
MPUSH a 20        → 20
MINSERT a 0 10   → 10
MINSERT a 2 30   → 30
MINSERT a 1 15   → 15
PRINT a          → [10 15 20 30]
MSET a 2 -1      → -1
MDEL a 1         → 15
PRINT a          → [10 -1 30]
MLEN a           → 3

Индекс:  0    1    2
       ┌────┬────┬────┐
Данные:│ 10 │ -1 │ 30 │
       └────┴────┴────┘
```

### Списки

Заменить `X` на `F` или `L`, использовать отдельные имена/файлы:

```text
XPUSH list 20
XPUSHFRONT list 10
XPUSHBACK list 40
XPUSHBEFORE list 2 30
XPUSHAFTER list 1 25
PRINT list       → [10 20 25 30 40]
XREVERSE list    → [40 30 25 20 10]
XDELBEFORE list 2 → 20
XDELAFTER list 1  → 30
XDELVAL list 25   → TRUE
PRINT list        → [10 40]

Односвязный: head → [10] → [40] → null
Двусвязный: null ← [10] ⇄ [40] → null
                   head   tail
```

### Стек и очередь

```text
SPUSH s -1; SPUSH s 2; SPUSH s 3
PRINT s → [3 2 -1]
SPOP s  → 3, следующий SPOP → 2, следующий → -1

Вершина → [3] → [2] → [-1]

QPUSH q -1; QPUSH q 2; QPUSH q 3
PRINT q → [-1 2 3]
QPOP q  → -1, следующий QPOP → 2, следующий → 3

Голова → [-1] → [2] → [3] ← Хвост
```

Здесь `;` разделяет отдельные запросы в описании, а не является синтаксисом `--query`.

### АВЛ

```text
TINSERT t 10; TINSERT t 20; TINSERT t 30
TINSERT t 40; TINSERT t 50; TINSERT t 25
PRINT t      → [10 20 25 30 40 50]
TGET t 25    → TRUE
ISMEMBER t 99 → FALSE
TINSERT t 25 → FALSE (дубликат)
TDEL t 50    → TRUE
PRINT t      → [10 20 25 30 40]

До удаления: упорядоченный обход → 10 → 20 → 25 → 30 → 40 → 50
После:       упорядоченный обход → 10 → 20 → 25 → 30 → 40
```

Файл сохраняет ключи, не конкретную форму дерева; после каждого восстановления
выполняется балансировка. Проверки высот, порядка и баланса выполняются также
на уровне узлов, а не только по тексту обхода.

## Проверка программы

- C++: тесты операций массива, списков, стека/очереди; 1000 случайных изменений
  двусвязного списка со сверкой обеих цепочек; 5000 изменений АВЛ со сверкой с
  `std::set`, проверкой высот и баланса после каждой операции.
- Go: по 2000 изменений каждого вида списка с проверкой связей и порядка;
  2000 операций массива со сверкой с эталонным срезом.
- Общие CLI-тесты: все команды, пустые структуры, индексы вне границ, отрицательные
  числа, предельные int32, повторяющиеся значения, неверные команды, повреждённые
  файлы, ошибки сохранения. Каждый запрос запускает новый процесс — это проверяет
  сохранение и повторную загрузку, а не только состояние в памяти.
- Взаимодействие C++ и Go: чтение и изменение общего файла без потери данных АВЛ.

Тесты запускаются командой из README; их результат нужно приложить к сдаваемому
отчёту, при необходимости со скриншотами терминала по требованиям преподавателя.

## Вывод

Реализованы операции над шестью структурами, командный интерфейс и файловое
хранение. Выбор структуры определяет стоимость операции в памяти; стоимость
сериализации нужно учитывать отдельно. Повороты АВЛ сохраняют логарифмическую
высоту, а проверки граничных случаев защищают структуры и сохранённые данные.
